# Chromis 1.4.0 (build 8)

Previous release: 1.3.1+7. A **minor** bump: three things that are new to use
and nothing removed, so semver says 1.4.0. Bumped in `pubspec.yaml` and
`AboutInfo.appVersion` - Play rejects an upload that reuses a versionCode, so
the `+8` is not optional.

**Build it on Flutter 3.44.9**, the version CI pins - see 1.3.1.md for why
neither an older 3.44 nor 3.47 will do.

## Play Console "What's new"

Paste `whatsnew-1.4.0.txt` verbatim. Longest is de-DE at 484 of 500, counting
the newlines twice; `python tool/check_store_listings.py` measures it.

## What is in it

**Resize image.** The top bar's size button opens one sheet with two tabs:
Canvas changes the canvas around the layers, as before; Image scales the whole
picture, with every photo resampled by the method the user picks - Nearest
neighbour, Bilinear, Bicubic or Lanczos, computed on the CPU so the named
method is the one that runs. One undo step. The photo import cap rises from
2048 to 4096 px with it, and the layer scale range now grows with the canvas.

**Fill in: Best quality or Low memory (#68).** Remove object's Fill in used to
try MI-GAN and fall through to content-aware fill with no say in which ran.
The user now chooses, by what it costs: Best quality (MI-GAN, 454-460 MB peak
on a 2048 px photo) or Low memory (content fill alone, 39-46 MB). The first
fill asks, with a recommendation based on the phone's RAM.

**Fonts.** 17 bundled caption fonts instead of 5 - twelve new ones, every one
of them covering the full alphabet of all six app languages - plus the fonts
already on the phone, read from Android's own font directories and limited to
the families `fonts.xml` offers by name. The Text and Bubble panels show one
font field in place of the old strip of chips; it opens a searchable list in
three sections (In the app, Your fonts, On this device) with font import at
the end. A device font is loaded only when its row is shown or a project uses
it, and only the face nearest w700.

One visible migration: a font imported before this release whose name is now a
bundled family (Lobster, Anton, Kalam ...) or the UI font (Manrope) is renamed
on first launch - "Lobster" becomes "Lobster 2" - so the user's file and the
bundled one stay two fonts. A project that used the old name draws the bundled
face of that name, which for a file called Lobster.ttf is almost certainly the
same typeface.

**Limits say so.** A pinch at a layer's smallest or largest size shows a badge
on the canvas and gives one light haptic tick; a typed canvas size past 8192
px says why Apply is off; and the Bubble panel says when the caption already
fills the bubble, the point past which the Size slider moves and the canvas
does not.

## How it was verified

Host: `flutter analyze` clean, `flutter test` green (1,175).

A second review of the fonts commit found ten issues, all fixed with a test
each, every one of which fails without its fix: imported names reserved before
any device font loads; old imports clashing with a bundled or UI family
renumbered; the picker usable with the keyboard up in landscape; a failed
import reported and retryable; a failed scan or load retried instead of
remembered; the limit badge with hysteresis (no flicker, one tick per
arrival) and covering a collage cell's cover floor; the bubble note
memoized and re-measured when a font lands; names differing only by a space
listed as two fonts.

On the API 37 emulator (`sdk_gphone16k_x86_64`, 16 KB pages):

- `integration_test/device_fonts_device_test.dart` - every bundled caption font
  resolves on a real text engine; the scan finds 9 families in about 100 ms
  (Carrois Gothic SC, Coming Soon, Cutive Mono, Dancing Script, Droid Sans
  Mono, Noto Serif, Roboto, Roboto Flex, Source Sans Pro); a registered device
  font changes how text measures; an export of a caption in a device font
  nobody had loaded yet is drawn in that font, not the fallback.
- The whole BDD suite (`./e2e.ps1`), including "Pick a font" through the new
  field and search: 63 of 67 on the first run. The other four - background
  removal, PNG and JPG export, "a Pro user no longer sees the upsell" - are
  the entitlement trap CLAUDE.md describes under the store listing: the
  emulator's Play Store answers "not owned", `reconcileEntitlement` revokes
  the seeded Pro, and the AI and export steps meet a live rewarded ad. With
  the Play Store disabled, as `capture_store_shots.py prepare` does, all
  three features pass (6 of 6).
- By hand, with screenshots: the picker in light theme with all three
  sections; picking a device font (Dancing Script) on the canvas and in the
  field; a cold restart drawing it again on Home's thumbnail; the bubble's
  "fills the bubble" note; the size sheet's limit note; the pinch badge at
  600%; Resize image 2048 -> 4096 with Lanczos (about 4 s, resident memory
  +143 MB at peak on the debug build) and its undo.

## Not verified, and worth watching

- **AI tools on a 4096 px photo.** The import cap doubled, so a photo can now
  be four times the pixels the memory figures in CLAUDE.md were measured on,
  and the AI tools decode their input in full. Not measured on a device: the
  rewarded ad in front of every AI run uses the live units, which must not be
  played on our own hardware. Watch the #66 cluster ("Input dispatching timed
  out", `nativePollOnce`, 2 GB phones) in Android vitals.
- **Device fonts on OEM builds.** Samsung, Xiaomi and Pixel all ship their own
  faces and their own `fonts.xml` entries; only AOSP's was seen. A phone whose
  config cannot be read falls back to offering every Latin font file.

## Store listing

The listing copy in all six languages now says 17 fonts plus the phone's own
(`check_store_listings.py` counts `AppFonts.bundledFonts`). The captions in
`tool/store_copy.py` say 17 too, but the composed screenshots were **not**
regenerated: the bubble capture still shows the old row of font chips, so it
needs a new capture session (`capture_store_shots.py`) before the images are
rebuilt.
